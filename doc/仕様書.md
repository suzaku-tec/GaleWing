# GaleWing 仕様書

## 1. 文書情報

- 対象: GaleWing
- 対象システムの機能、データ、運用設定をまとめる。画面操作は [画面仕様](画面仕様.md) を参照する。

## 2. システム概要

GaleWing は RSS/Atom を中心に Web サイトのフィードを収集し、既読管理、カテゴリ分類、検索・集計、翻訳、関連情報表示を行う Web アプリケーションである。Thymeleaf の画面と JSON を返す HTTP エンドポイントを提供する。Google Alerts、World News API、News API、Ollama、LibreTranslate、SearXNG、RSSHub/RSS-Bridge などとの連携機能を含む。

## 3. 構成

| 領域 | 責務 |
|---|---|
| `controller` | 画面表示、HTTP 入出力、サービス呼び出し |
| `service` | フィード取得、検索、分類、翻訳、外部 API、分析 |
| `repository` | SQL による永続化と検索 |
| `entity` / `dto` | 永続データおよびリクエスト・レスポンス構造 |
| `task` | 定期実行・手動実行可能なバックグラウンド処理 |
| 画面 | Thymeleaf による Web 画面 |
| データアクセス | SQL による永続化と検索 |
| 画面操作 | JavaScript/TypeScript による動的な操作 |

Java 21 を対象とする Gradle プロジェクトで、Spring Boot Web / Thymeleaf を利用する。DBアクセスには MirageSQL、JdbcTemplate 等を利用する。

## 4. 主なデータ

| データ | 主な項目・役割 |
|---|---|
| Site (`site`) | UUID、タイトル、Web URL、フィード URL、favicon、更新日時、翻訳有効フラグ |
| Feed (`feed`) | タイトル、所属サイト UUID、記事 URL、URI、著者、公開日時、既読/閲覧状態、画像、本文、翻訳タイトル |
| Category / FeedCategory | カテゴリとフィードの分類・関連付け |
| FeedClassification | 分類カテゴリ、スコア、適用ルール、分類器バージョン、分類日時 |
| View / ViewSite | 複数サイトをまとめるカスタム表示 |
| Settings / FunctionCtrl | アプリケーション設定・機能フラグ |
| Podcast / PodcastFeed | Podcast とエピソードフィード |
| Stack | 保存リスト |
| Stats / NewsSummary / AIRecommendFeed | 統計、ニュース要約、AI 推薦データ |

## 5. 機能仕様

### 5.1 フィード・サイト管理

- トップ画面はサイト別未読件数とビュー一覧を表示する。`/?uuid=...` はサイトまたはビューを識別する。
- `/feedlist` は `uuid` 省略時に全フィード、指定時はサイトまたはビューのフィードを返す。
- 翻訳タイトルがある記事は一覧用タイトルに `[翻訳]` を付ける。`feed-img` 機能フラグが有効な場合、レスポンス上の画像 URL を除去する。
- 記事単位の既読、対象サイトの一括既読、URL リストの既読処理を提供する。URL リストはキュー投入後に非同期処理する。
- サイト追加では URL を検証する。RSS-Bridge URL、`.xml` URL、通常の Web ページを処理し、通常ページでは RSS/Atom リンクを探索する。取得したフィードからサイトと記事を登録し、既存サイトは重複登録しない。
- フィード更新は全サイトまたは指定サイトを対象に実行できる。新規記事は重複 URL と保持期間を確認して登録する。個別更新ではタイトルタグ分析も非同期で依頼する。
- OPML のインポート/エクスポート、サイト削除、favicon 更新、最終更新日の参照を提供する。

### 5.2 閲覧・整理

- サイトフィード、カテゴリ、ビュー、関係情報を管理する。ビューは複数サイトを束ね、ビュー単位でフィード表示・一括既読ができる。
- 記事の関連付け、保存リスト（Stack）、Podcast の登録・同期・既読管理を提供する。
- ルールベース分類器は主カテゴリ、カテゴリ集合、スコア、適用ルールを保存する。

### 5.3 分析・外部情報

トレンド分析、統計、閲覧率、ランキング、レポート、キーワード検索、外部ニュース取得、AI 要約・推薦、機械翻訳を扱う。RSS-Bridge 対応として Instagram、Reddit、Bluesky のコンテンツ一覧取得処理がある。入出力の詳細は各機能の画面・操作に従う。

## 7. バックグラウンド処理

| 処理 | 設定キー / 起動契機 | 内容 |
|---|---|---|
| 自動フィード更新 | `update.scheduler.cron` | Google Alerts と RSS を取得し、新規・保持期間内記事を登録。ルール分類も保存 |
| 既読記事削除 | `readFeed.delete.scheduler.cron` | `days.retained` を使い古い既読記事を削除 |
| 自動翻訳 | `translate.scheduler.cron` | 翻訳対象サイトの記事タイトルを翻訳・保存 |
| フィードカテゴリ更新 | `update.feed.category.cron` | フィードカテゴリの定期更新 |
| トレンド分析 | `trend.scheduler.cron` / `analyze.scheduler.cron` | トレンド分析系タスク |
| Qiita ランキング | `qiita.ranking.scheduler.cron` | ランキング取得・保存 |
| その他 | `/task/executeTask` | Spring 登録済み `Runnable` を名前で選択して実行 |

定期処理の実行間隔はアプリケーション設定で変更できる。

## 8. 設定・外部依存

- 既定ポートは `8080`。TLS キーストア設定も `application.properties` にある。
- `application.properties` に加え、`.env`（任意）と `news-classification.yml` を読み込む。
- `DBConfig` は主データソースを PostgreSQL (`localhost:5432/postgres`)、カスタム RSS 用を `customRss.db` SQLite として構成する。主データソースの Dialect に SQLiteDialect が設定されているため、実運用環境の DB 設定と合わせて確認すること。
- Ollama は `http://localhost:11434`、SearXNG は `http://localhost:18080/search`、RSSHub は `http://localhost:3000` を既定接続先とする。
- 外部 API の認証情報など環境依存値は `.env` 等で与える構成を含む。

## 9. 非同期処理

Spring `@Async` を利用する。`taskExecutor` はコア/最大 2 スレッド、キュー 500 件。タイトル分析用 executor はコア 2、最大 10 スレッド、キュー 100 件。

## 10. エラー・制約

- RSS の取得・解析失敗を空結果として扱う箇所がある。詳細は各機能のエラー処理に従う。
- サイト追加 URL は `http` または `https` を許可するバリデーションを通り、不正 URL は `IllegalArgumentException` となる。
- 保持期間、重複判定、既読状態の詳細はデータ管理ルールに従う。
- エンドポイント表はパス索引であり、認証要件、HTTP ステータス、全パラメータ、全レスポンススキーマを定義する API 定義書ではない。
